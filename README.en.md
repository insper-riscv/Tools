# RISC-V Tools

🌐 [Português](README.md) · [English](README.en.md)

`riscv-tools` is a Python package that builds, simulates, runs, and certifies test programs for bare-metal RISC-V. Each project describes its flow in a `config.yaml`, and the same compiled test runs in two ways: on real hardware, through the JTAG port, or in the cocotb/GHDL simulation.

Results are checked against references (goldens), generated by Spike or versioned in the project's repository.

The package has one module per responsibility, each with its own `__config__.py` of defaults. The consuming project's `config.yaml` overrides those defaults, and the complete reference is in [docs/configuration.md](docs/en/configuration.md).

It is designed to run on a workstation with all the tools installed, or inside the CI Docker images of the [Infra](https://github.com/insper-riscv/Infra) repository.

## Usage

```bash
uv sync
uv run riscv-tools --config /path/to/project/config.yaml compile --emit mif
uv run riscv-tools --config /path/to/project/config.yaml compile --emit mif --only test-a,test-b
uv run riscv-tools --config /path/to/project/config.yaml compile --emit asm
uv run riscv-tools --config /path/to/project/config.yaml run
uv run riscv-tools --config /path/to/project/config.yaml run --exclude test-a,test-b
uv run riscv-tools --config /path/to/project/config.yaml generate-golden \
    build/real/some_test.elf --march rv32im --start 0x10 --end 0x20 --out golden/some_test.json

# Simulation (needs the "sim" extra: cocotb + cocotb-tools, and GHDL on PATH)
uv sync
uv run riscv-tools --config /path/to/project/config.yaml compile --emit hex
uv run riscv-tools --config /path/to/project/config.yaml sim
uv run riscv-tools --config /path/to/project/config.yaml sim --only test-a,test-b
```

See `riscv-tools --help` for the full subcommand list (`compile`, `generate-header`, `generate-golden`, `write-rom`, `zero-ram`, `dump-ram`, `console`, `display`, `program`, `htif read|restart`, `run`, `spike-run`, `sim`, `certify`, `certify-board`, `profiles`, `vhdl-sort`, `check-memory-map`, `generate-memory-map`, `generate-config-pkg`, `check-paths`, `check-boards`, `check-tree`, `sources`, `ipxact`, `check-vhdl-style`, `vsg-config`, `vsg-rules`, `vhdl-files`, `platform`, `flash-image`, `timing-paths`, and `board generate`).

```bash
# vhdl-sort needs no --config; pure file-content analysis, e.g. wired
# into a Makefile's own VHDL-syntax-check target:
uv run riscv-tools vhdl-sort src/**/*.vhd
```

## Development

```bash
uv sync --group dev
uv run pytest
```

Tests that need GHDL, the RISC-V GCC or Spike skip when the tool is missing.
Each module's doc lists its prerequisites and the tests that cover it. The
tests check this package's own tooling; the processor is verified by the
consuming project's suites.

`tests/test_static_analysis.py` runs `ruff`, `pyright` and `deptry` over the whole
package, so it belongs to no single module.

### Running the tests in Docker

The `Dockerfile` starts from the `ci-elf` image that
[insper-riscv/Infra](https://github.com/insper-riscv/Infra) publishes
(`ghcr.io/insper-riscv/ci-elf`, see its `docs/en/docker/ci-elf.md`): GHDL,
the RISC-V GCC with picolibc, a Spike with its debug module away from address 0,
and `uv`. It adds
this project's dependencies, so nothing is skipped and nothing is compiled:

```bash
docker build -t riscv-tools-tests .
docker run --rm -v "$PWD:/workspace" riscv-tools-tests
docker run --rm -v "$PWD:/workspace" riscv-tools-tests tests/test_sim_runner.py -v
```

The base image is the `latest` of `ci-elf`. To test against a
specific publication, pass its `sha-` tag:

```bash
docker build --build-arg TOOLCHAIN_IMAGE=ghcr.io/insper-riscv/ci-elf:sha-<commit> \
    -t riscv-tools-tests .
```

The `tests` workflow builds this image and runs the whole suite on every push
and pull request.
